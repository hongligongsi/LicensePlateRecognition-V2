# 参考实现评估：YOLO26-plate（`yolo26-plate-main.zip`）

对这份基于 YOLO26-pose 的车牌检测+识别参考实现（仓库内嵌 ultralytics 源码）
做一次通读，回答一个问题：**还有哪些值得学？**
结论是——可学的不多，且多数受硬约束限制；
反倒顺带在我们自己的代码里查出一个真 bug。

> 说明：其识别部分的字符表/归一化/dedup 写法与若干公开车牌 CRNN 项目高度相似，
> 但我在离线环境无法核实确切出处，故不做来源断言，只对**代码本身**做评估。

---

## 0. 结论速览

| 维度 | 参考实现 | 本项目（lpr-v2） | 建议 |
|---|---|---|---|
| 检测 | YOLO26 **pose**，回归 4 角点 + 单/双层类别 | CV 轮廓 + `minAreaRect` 四边形 | 思路可学，**当前无法落地**（无 torch、无训练数据） |
| 透视矫正 | `four_point_transform`（pose 角点） | `_warp_plate`（轮廓四边形） | **我们已有**，且鲁棒性更好 |
| 识别 | 车牌专用 CRNN 168×48，78 类，750KB | `cv`：SVM（弱）／`deep`：RapidOCR 通用 OCR | 值得学的核心（见 2.1） |
| 车牌颜色 | **识别网络的第二个 head**，5 类 softmax | HSV 启发式 + 比例置信度 | 值得学其「颜色应学出来」的思路 |
| 双行牌 | 固定比例切分 `5/12` + `1/3` | 投影分析 + 裁边框 + 单行防线 | **我们的更通用**，不学 |
| 字符集 | 不含 I/O | 不含 I/O | 已一致 |
| 特殊号牌 | 武警旧式、危险品 2~3 字后缀 | 港澳入出境（他们没有）、危险品底色建模 | 互补，见 2.3 |
| 工程化 | 无 CI、无 lint、tests/ 全是 ultralytics 自带、**无任何精度数据** | CI + ruff/mypy + 478 测试 + 回归基线 + 弱监督评测 | **我们明显更强** |
| 加固 | `onnx_infer.py` 有 4 处硬编码单图补丁 | 无硬编码补丁（已核查） | 反面教材 |

## 1. 三条硬边界：为什么很多好东西拿不来

**(1) 环境跑不了、也转不了他们的权重**

```
torch       MISSING
onnx        MISSING
onnxruntime OK 1.31.0
```

仓库只提供 `.pt`（检测，64MB）与 `.pth`（识别，750KB），**没有 ONNX**。
要跑（或转 ONNX）都必须先装 torch，而本环境 PyPI 不通。
所以「直接用他们的模型」这条路目前是封死的。

**(2) 许可证冲突：AGPL-3.0 vs 我们的 MIT**

仓库根 `LICENSE` 是 **GNU AGPL-3.0**（整个仓库是 ultralytics 的 vendored 副本 +
车牌改造，3.8MB 源码）。把它的代码或权重搬进 MIT 项目会导致**许可传染**。
个人自用无所谓；一旦公开分发就必须整体转 AGPL，或把模型做成
「用户自行下载、不进仓库」的可选件并明确声明许可。

**(3) 他们没有精度数据**

`README_plate.md`、`docs/`（其实就是 ultralytics 文档）里**没有任何车牌
准确率/mAP 数字**，`tests/` 也没有一项评测车牌识别质量。所以无从引用其效果——
这反过来更说明本项目自建的 `tools/eval_weak.py` + `tests/baselines/` 有价值。

## 2. 真正值得学的三条

### 2.1 颜色不该只用 HSV 阈值——它是识别网络的第二个 head

`plateNet.py::myNet_ocr_color` 在字符分支之外挂了一个颜色分支：

```python
self.conv1  = nn.Conv2d(cfg[-1], 12, 3, stride=2)   # 共用 backbone 特征
self.color_classifier = nn.Conv2d(12, color_num, 1) # 5 类
x_color = self.gap(self.color_bn(self.color_classifier(self.relu1(self.bn1(x)))))
```

也就是**颜色与字符共享同一份特征**，在矫正后的 ROI 上端到端学出来，
并且天然带颜色置信度（`color_conf`）。这解释了为什么它的颜色判定稳。

对照我们：`locate.detect_color()` 是 HSV 阈值 + 面积比例，靠人工调
`color_ratio` / `color_row_ratio` 等参数。**根本差异是「学出来 vs 定阈值」**。

可落地性：不能照搬权重（许可 + 无 torch）。可走的路有两条——
自训一个小分类头（需要数据），或接入一个许可宽松的车牌专用 ONNX 识别模型
作为第三个引擎。**短期不动，但值得记为方向。**

### 2.2 关键点式检测：版式与角点在检测阶段一次性给出

他们的检测器是 pose 任务：`kpt_shape: [4,2]` + `flip_idx: [1,0,3,2]`，
类别 `0: single / 1: double`。于是「4 个角点用于透视矫正」和
「单层还是双层」都由网络直接给出，属于**learned 版式判定**。

对照我们：角点来自 `cv2.minAreaRect(contour)`，版式来自
`measure_layout()` 的投影启发式。我们的做法不依赖训练数据、更通用，
但在数据充足的场景下他们的更稳。

顺带一个有价值的坑：`verify_flip_idx.py` 说明**水平翻转增广必须重排关键点索引**
（`keypoints[:, [1,0,3,2], :]`），写错会静默毁掉训练。我们不做增广，
暂不受影响，但若将来引入翻转增广需记住这条。

### 2.3 号牌规范的两处真实增量

他们的 `onnx_infer.py` 里有一个比我们更细的规范正则（`_PLATE_PATTERN`）。
逐条比对后，**只有两处我们确实缺**：

| 项 | 他们 | 我们 | 影响 |
|---|---|---|---|
| 武警旧式号牌 | `WJ` + 2 位机构码 + (`字母`+4 位 \| 5 位数字) | 仅 `WJ`+省+4 位+字母数字（现行式） | 旧式牌会被判非法 → 漏报 |
| 危险品后缀 | `(?:学\|危\|危险\|危险品\|港\|澳\|挂)` | 仅单字 `危` | 「京A1234危险品」经 `_extract_plate` 截成「京A1234危」仍合法，实际影响小 |

另有 **3 处两边不一致、值得人工核对**（我不确定谁对，不敢下结论）：

1. **使领馆排列相反**：我们 `使[0-9]{6}`（使字头在前），他们 `[0-9]{6}使`（在后）。
   按「使领馆号牌以『使』字头开头」的说法，我们这条更可能正确，建议核对 GA36。
2. **警用第 3 位**：他们允许字母 `[A-D0-9]`，我们只允许数字。
3. **军队号牌第二位**：他们用受限字符类 `[A-DJ-PR-TVY]`，我们用全字母集。

## 3. 我们已经领先、不需要学的地方

* **透视矫正在已经存在**（`locate._warp_plate`），而且实现比他们稳：
  尺寸 `max(w,1)/max(h,1)` 防退化、`round` 而非 `int()` 截断、
  `borderMode=BORDER_REPLICATE` 避免黑边，并会在矫正图上**二次判色**取更优结果。
  他们的 `four_point_transform` 用 `int()` 截断，退化四边形可能算出 0 尺寸。
* **双行牌切分**：我们用「裁左右边框 + 行投影 + 单行防线 + 行高相似性」四项判据；
  他们是固定比例 `5/12` 与 `1/3`。我们的对任意宽高比成立，他们的依赖版式先验。
* **特殊号牌覆盖更广**：港澳入出境（`粤Z…港/澳`）他们**没有**；
  危险品底色我们用独立 `PlateColor.HAZMAT` 建模，他们没有。
* **字符集已排除 I/O**：`L="ABCDEFGHJKLMNPQRSTUVWXYZ"`、`AN="A-HJ-NP-Z0-9"`，
  与他们等价——这条**不用改**。
* **工程化**：CI（ruff+mypy+多版本矩阵）、`py.typed`、478 项测试、
  行为回归基线、弱监督评测工具链。他们 tests/ 全是 ultralytics 自带用例。

## 5. 顺带查出：我们自己的一个真 bug（由对照触发）

### 5.1 现象

`locate._order_quad` 的 docstring 写着：

> 这里用标准的"x+y 最小/最大" **+ 叉积判断**，鲁棒得多

但实现里**只有 sum/diff，没有任何叉积**：

```python
s = pts.sum(axis=1)
ordered[0] = pts[np.argmin(s)]   # 左上
ordered[2] = pts[np.argmax(s)]   # 右下
d = np.diff(pts, axis=1).ravel()
ordered[1] = pts[np.argmin(d)]   # 右上
ordered[3] = pts[np.argmax(d)]   # 左下
```

（参考实现的 `order_points` 也是同一套，所以这不是"可以学"的点，
而是**双方共有的缺陷**。）

### 5.2 几何层实证：≥46° 时排序错位

构造 220×70（车牌比例 3.14:1）的旋转矩形，检查排序后
`top/bottom/left/right` 边长是否构成正向宽图：

```
旋转角   top     bot     left   right   结果
    0   220.0   220.0    70.0    70.0   OK
   44   220.0   220.0    70.0    70.0   OK
   46    70.0    70.0   220.0   220.0   错位!
   60    70.0    70.0   220.0   220.0   错位!
   89    70.0    70.0   220.0   220.0   错位!
```

排序一旦错位，`warpPerspective` 会把车牌**旋转 90° 输出成竖图**，
后续字符识别必然失败。

### 5.3 端到端实证：影响是"部分致命"

| 样张 | 旋转 | 定位候选 ROI（高,宽） | 走的路径 | 结果 |
|---|---|---|---|---|
| `single_yellow.jpg` | 0° | (31,129)… | guided | `皖K66666` ✓ |
| `single_yellow.jpg` | 50° | (366,339) 整车大小 | **full 兜底** | `皖K66666` ✓（运气好） |
| `single_blue.jpg` | 0° | (522,1104)… | full | `辽DU4356` `浙B029L7` ✓ |
| `single_blue.jpg` | **50°** | (74,187) 比例 2.53 ≈ 车牌 | **无** | **零结果** ✗ |

解读：`single_yellow` 靠全图 OCR 兜底侥幸活下来（全图 OCR 在 50° 下仍
勉强可读）；而 `single_blue` 在 50° 时定位**已经找到了车牌**
（ROI 比例 2.53 落在车牌区间），但矫正后的图是 90° 竖的，
引导路径失效、全图兜底也读不出 → **整体漏识**。

所以：这不是理论风险，是**低频但真实**的漏识来源。

### 5.4 修法（未实施）

`_order_quad` 改成旋转鲁棒：

1. 先按**质心极角**排序，得到正确的**环形顺序**（不再是 x+y 极值）；
2. 在环上确定"长边"：取两条对边中较长的那对；
3. 取其中**中点 y 较小**的那条长边作为上边（对任意 \|θ\|<90° 成立：
   两条长边在 y 方向的间距为 `h·cosθ > 0`，上边恒在上），
   其起点为左上、终点为右上；
4. 按环序补齐右下、左下，保证输出 `width > height`。

预期收益：恢复上表中 `single_blue` 那类「定位已命中、只是矫正歪了」的样本；
风险是改动核心几何，**必须过** `tests/test_regression_baseline.py` 的
11 张行为快照 + 全量 478 项测试。
